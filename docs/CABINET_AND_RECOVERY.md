# Кабинет и восстановление — 23.09.2026

## Подключение и экраны партнёра — 03.10.2026

Новый партнёр сразу после `/start` видит приветствие, ссылки на условия и политику,
версию документов и кнопку «Принимаю оба документа». Только явное принятие открывает
два шага анкеты: компания и проект. При обновлении версии во время заполнения бот
возвращает к документам; согласия с прежней версией недостаточно для отправки заявки.
Данные заявки и обе записи согласия сохраняются совместно при отправке анкеты.
Без настроенных ссылок приём заявок закрыт. Для уже отправленной заявки показывается
статус без предложения отправить её повторно.

Основные партнёрские экраны объясняют назначение раздела, следующий шаг и формат ввода.
Кнопки используют Telegram `style=primary` (синий). Нажатая callback-кнопка получает
`style=success` (зелёный) перед переходом; сбой визуального обновления не блокирует
действие. URL-кнопки открываются самим Telegram и не сообщают боту о нажатии, поэтому
остаются синими. Отрисовка стилей зависит от версии клиента Telegram.

## Ключ поставщика в заявке

Администратор открывает «Заявки» → карточку и отправляет ключ отдельным сообщением
прямо в этом чате. Кнопка «Добавить ключ» открывает тот же шаг без ручного ввода UUID.
Бот проверяет ключ у поставщика, удаляет исходное сообщение, если Telegram позволяет,
и показывает компанию, проект и Telegram ID для подтверждения подключения.
До подтверждения хранится зашифрованный ключ в действии, связанном с конкретной заявкой
и администратором; plaintext не попадает в состояние диалога или ответы.

«Подтвердить» повторно проверяет ключ и атомарно сохраняет credential заявки,
одобряет аккаунт и переносит привязку ключа к партнёру. Повторное нажатие не создаёт
новый credential или аккаунт. Неверный ключ и уже рассмотренная заявка не изменяют
привязки. Если ключ уже привязан через административный API, его не нужно вводить заново.
Замена введённого ключа, выход из карточки и `/cancel` отменяют прежнее подтверждение.
Старые кнопки одобрения без ключа также переводят к его вводу.

## Бесплатные тесты

Активный партнёр открывает «Бесплатные видеотесты», выбирает production-видеомодель
и отправляет prompt либо полный native JSON текстом/файлом до 1 МиБ. JSON позволяет
передать все поддерживаемые параметры, включая ссылки на image/video/audio references.
Параметры проверяются тем же контрактом, что и `/v1/videos/generations`, и не урезаются.
Первый API-ключ автоматически не создаётся.

Два принятых запуска за всю историю Telegram ID. PostgreSQL сериализует выдачу,
повтор подтверждения возвращает прежнюю генерацию. Удаление аккаунта не удаляет
entitlement; повторная регистрация не выдаёт ещё два запуска. Валидация/отказ admission
до принятия не расходует лимит; уже принятая попытка, в том числе с ошибкой upstream,
остаётся использованной. Неопределённый платный запрос не запускается заново.

Розничные rates в snapshot равны нулю, закупочные rates сохраняются. Актуальный
working-capital gate действует и на тесты. Финальное usage учитывает реальный расход
владельца и оставляет partner charge равным 0 ₽. Публичный API не принимает льготу:
поле с похожим именем в native JSON не меняет расчёт стоимости.

Результат приходит через durable Telegram outbox. Подписанная ссылка нашего proxy
действует до 24 часов и не раскрывает provider URL/ключ. Это срок доступа к proxy,
а не гарантия хранения у ArgoLink. Поиск UUID в кабинете позволяет получить новую
ссылку, пока upstream хранит результат. Аккаунт должен оставаться активным.
Ссылки следует хранить как bearer credentials; access logs proxy их не записывают,
application formatter скрывает подпись. Результат передаётся потоком без хранения bytes.

## Provider circuit

Состояние хранится в PostgreSQL, а не Redis/process memory. Начальный достаточный
sample — 20 terminal outcomes. Отключение при >10% provider errors за 5 минут или
>5% timeout за 10 минут. Персональные quota/validation/auth rejects не отключают
поставщика для всех партнёров. Экономические убытки сами по себе circuit не открывают.

Открытый circuit запрещает новые native/legacy admissions; queued задачи ожидают,
polling принятых задач продолжается. Admin получает одно уведомление на отключение.
Generation worker делает бесплатный `GET /v1/models` не чаще раза в минуту. После
трёх успешных проверок проходит одна реальная задача; нужны три успешные задачи
подряд для закрытия circuit. Платных синтетических health requests нет.

Любая наблюдаемая provider-side ошибка в recovery снова открывает circuit. Пропавшая
проба после processing timeout также открывает circuit без повторной отправки.
В течение 10 минут после восстановления первая новая provider error отключает
поставщика по ускоренному сценарию. Восстановление уведомляет администратора один раз.
Конкурирующие workers/API процессы не могут занять две recovery-пробы одновременно.
История circuit/outcomes и notification outbox попадает в обычный encrypted backup.

## Пороги, документы и администрирование

Low-margin threshold по умолчанию 30%; приоритет configuration → model → global.
`-` в форме удаляет override. История append-only: scope, actor, timestamp, old/new.
Настройка влияет на следующую оценку инцидентов, не меняет цены/историческую маржу
и не блокирует положительную экономику. Одно уведомление на инцидент; после
восстановления и нового падения создаётся новый эпизод. API: `/api/v1/billing/margin-thresholds`.

При изменении `LEGAL_DOCUMENT_VERSION` активным партнёрам создаётся по одному
устойчивому уведомлению с TERMS_URL/PRIVACY_POLICY_URL. «Документы» записывают явное
согласие с отображённой версией. Старый callback не принимает новую версию незаметно.
Публикация самих юридических документов и их содержание — deployment input.

Admin → «Цены, возвраты и сверки» содержит пошаговые формы с итоговым подтверждением:
retail/procurement prices, margin thresholds, возврат, вывод/обратная корректировка,
ручная коррекция RUB, invoice/generation reconciliation, включение модели/gates/
capabilities, импорт reviewed catalog и управление provider credentials. Вывод и
возврат записывают подтверждённую операцию, не переводят деньги автоматически.
Ключ поставщика не отражается в подтверждении и хранится только зашифрованным.
Admin → «Состояние» показывает DB/Redis и фазу восстановления провайдера.

Все подтверждения связаны с Telegram ID, истекают через 15 минут и повторно проверяют
admin role и финансовые условия. PostgreSQL сохраняет диалог между перезапусками.
Живые сообщения пользователям при разработке не отправлялись: проверки используют
синтетические Telegram updates и изолированные provider transports.
